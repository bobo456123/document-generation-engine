# WI-0004 修复飞书重复截图资源的图片块绑定

## 结果

同一张本地截图被多个操作步骤引用时，发布到飞书后每个截图出现位置都有独立且正确的图片，不再出现空白图片块；单张截图和不同截图的既有发布行为保持不变。

## 背景

真实测试文档的最新修订包含三个截图出现位置，其中步骤 2 和步骤 3 复用了同一个资源 ID。本地 Markdown 预览正常，但飞书远端出现三个图片块且中间块没有图片。原因是发布器用资源 ID 作为唯一键保存图片块 ID，后一次出现覆盖前一次，随后两次上传都更新同一个远端块。

## 范围

- 按截图出现位置保存远端图片块绑定，并逐个上传和替换图片。
- 增加同一资源 ID 多次出现的发布器回归测试。
- 在已授权的飞书测试知识空间重新发布受影响文档，并只读核对每个图片块均有绑定。
- 记录发布审计和当前交接状态。

不包含截图内容重新采集、文档正文改写、飞书权限变更或其他发布协议调整。

## 约束

- 保持 `Publisher` 公共接口和现有文档、资源模型兼容。
- 不在仓库记录飞书凭证、令牌、Cookie、远端节点标识或业务项目绝对路径。
- 发布失败时继续保留远端旧正文；不增加不可安全重放的删除重试。
- 真实外部复验仅针对用户授权的测试知识空间，结果与自动化契约测试分开记录。

## 实施方案

在 `FeishuPublisher` 内部将图片块绑定表示为按 occurrence 排列的记录（截图资源 ID、资源文件和新建块 ID），创建每个图片块时追加记录，上传循环按记录逐条调用媒体上传和 `replace_image`。不再通过 `Record<assetId, blockId>` 反查块。回归测试使用两个步骤引用同一资源 ID，并断言两次上传和两次替换分别使用不同块 ID。

## 验收标准

- 同一资源 ID 出现两次时，两个远端图片块都收到一次上传和一次替换，块 ID 不相同。
- 不同资源 ID、多张截图、无截图和已有文档重复发布测试继续通过。
- 真实测试文档重新发布后，远端图片块数量与截图出现次数一致，所有图片块均有有效图片绑定。
- `pnpm check:docs`、`pnpm lint`、`pnpm typecheck`、`pnpm test` 和 `pnpm build` 全部通过。

## 证据

- 回归测试先在旧实现上复现了两个出现位置都指向后一个图片块的失败；修复后执行 `pnpm exec vitest run packages/publisher-feishu/src/index.test.ts`，22 个测试全部通过。
- 执行完整 `pnpm check`，文档检查、lint、类型检查、测试和构建全部通过；测试结果为 19 个测试文件、116 项测试通过。第一次沙箱运行因禁止绑定本机回环端口失败，随后在允许本机端口的环境重跑通过。
- 在用户授权的飞书测试知识空间执行 `bizdoc publish feishu`，既有文档节点复用且命令返回完成；发布后只读查询确认 3 个图片块均有有效图片绑定，图片块数量与截图出现次数一致。
- 本次修复未修改业务源码、文档正文或截图资源；代码、测试和验收文档已提交于 `2ebe7c0`。

## 残余风险

- 真实飞书复验依赖外部权限和网络，自动化测试使用客户端契约模拟，CI 不会自动验证远端页面渲染。
- 同一截图资源在多个步骤复用现在可以正确发布，但是否应复用同一业务截图仍由人工审核确认。
