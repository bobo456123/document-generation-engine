# 测试与验收规范

## 质量门

完整质量门为：

```bash
pnpm check
```

它必须包含文档检查、lint、类型检查、自动化测试和构建。单项命令用于定位问题，不能替代完成前的完整门禁。

## 覆盖原则

- 狭窄修改运行对应模块测试；跨模块契约、持久化或用户工作流变化扩大到集成测试。
- 解析器变更必须覆盖可信关联、未关联、冲突或降级场景。
- 文档生成变更必须覆盖 Schema、证据 ID、置信度和审核门禁。
- 发布变更必须覆盖幂等、部分失败、重试、资源预检和敏感错误脱敏。
- 外部飞书或 AI 验证结果必须区分自动化契约测试与真实环境验收。

## 证据记录

工作项和里程碑只记录实际执行的结果，不使用“预计通过”。无法运行的检查必须写明原因和残余风险；测试数量只在实际输出确认后更新。
