# WI-0002 简化 CLI 初始化、凭证、截图与飞书发布流程

## 结果

用户进入业务文档目录后，可以直接使用全局 `bizdoc` 完成初始化、分析、选择功能、生成、截图、审核和分层发布，无需反复传工作目录或手工查找内部 ID，也无需每次在 Shell 中临时设置凭证。

## 背景

MVP CLI 已跑通完整链路，但当前说明和命令暴露了工作目录、Feature ID、Document ID、Step ID、修订号、截图文件路径及飞书父节点等内部细节，适合调试但不适合重复使用。

## 范围

- 提供支持 `pnpm link:cli` 的本地开发 `bizdoc` 入口，并为未来 npm 包保留清晰迁移路径。
- 从当前目录向上发现 `.bizdoc/project.yaml`；旧目录参数继续兼容。
- 提供 AI 与飞书凭证的主动配置、状态检查和删除命令；环境变量继续支持自动化覆盖。
- 提供功能、文档和状态列表，并在终端交互环境中隐藏常用内部 ID。
- 提供旧文档分类迁移命令，保留已审核正文、证据和截图并创建待审核分类修订。
- 支持无文件参数选择截图，以及 macOS 交互截图后直接导入。
- 飞书发布自动确保“系统/业务模块/文档”层级并复用远端节点。
- 清理默认输出和帮助信息，同时保留 `--json` 或完整参数用于脚本调用。

不包含 Playwright 自动登录和自动遍历页面截图，也不发布 npm 在线包。

## 约束

- 旧命令在本版本继续可用，不破坏已记录的 MVP 工作流。
- 凭证不得写入项目 YAML、SQLite、日志或 Git；macOS 使用系统钥匙串，CI 继续使用环境变量。
- 钥匙串写入不得把真实值放入子进程参数；真实 macOS 行为必须验证非空回读，而不只验证模拟调用。
- 非交互环境不得等待终端输入，缺少必要参数时返回可执行的错误提示。
- 飞书系统和模块节点必须幂等；迁移既有根目录文档不得静默创建重复页面。
- 当前 MVP 数据库必须通过向前迁移继续使用。

## 实施方案

建立统一 Workspace Context 负责目录发现和配置加载；Credential Store 负责环境变量与系统钥匙串；CLI Selector 负责终端选择并保留非交互参数；Feishu Hierarchy Resolver 负责系统、模块节点和现有文档父级。CLI 只编排这些深模块，不重复实现状态查找。

## 验收标准

- 本地 link 后可在任意目录执行 `bizdoc --version`，进入项目目录后无需工作目录参数。
- `bizdoc auth` 可以安全配置、检查和删除凭证，命令输出不泄漏值。
- 功能、文档、步骤和最新修订可列表或自动选择；非交互模式行为确定且可测试。
- v0.1 已审核旧文档可在不重新生成正文的情况下补充业务分类，且新修订必须重新审核。
- 截图可以通过文件选择或系统截图导入，并继续创建不可变待审核修订。
- 飞书新文档路径为“系统/业务模块/文档”，重复发布不重复创建层级或文档。
- 旧命令兼容测试、凭证安全测试、层级幂等测试和完整 `pnpm check` 通过。

## 残余风险

- 当前全局入口依赖仓库中的 `tsx` 和 TypeScript 源码，只适合本地开发；可独立安装的 npm 产物需另立工作项。
- macOS 系统截图和文件选择器已有自动化契约测试，但图形界面交互仍依赖本机权限；其他系统必须显式传入图片路径。
- 飞书层级已完成一次真实测试空间复验；外部权限和页面状态仍可能变化，每次发布前继续执行预检。
- 模块名称默认参与稳定 ID 计算；修改模块名称表示重新分类，而不是批量重命名既有模块。并发发布和失效远端映射的修复流程仍需后续独立工作项。
