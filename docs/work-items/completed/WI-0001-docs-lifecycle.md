# WI-0001 建立文档全生命周期与 Agent 交接体系

## 结果

仓库具备从当前事实、候选路线图、工作项执行到里程碑归档的完整文档结构；新的开发者或 Agent 可以从固定入口确定当前状态、下一步行动和验收依据。

## 背景

MVP 完成后，需求、历史设计、Goal 状态和试点证据混在 `docs/` 根目录，缺少当前事实入口、工作项规范、架构决策记录和自动一致性检查。

## 范围

- 迁移并冻结 `v0.1 MVP` 历史资料。
- 建立当前状态、产品、架构、开发、工作项、里程碑和模板目录。
- 增加根 `AGENTS.md` 和用户 README 的开发文档入口。
- 增加 Markdown 链接、YAML 元数据、编号和活动工作项一致性检查。

不修改引擎运行时 API、数据库 Schema 或业务工作流。

## 约束

- 历史资料保持原始内容，只修正迁移后的内部链接。
- 路线图候选不视为已承诺范围。
- 文档不保存真实凭证、企业源码或用户绝对路径。
- 复用现有 `marked` 与 `yaml` 依赖，不引入新包。

## 实施方案

采用“当前有效文档 + 不可变里程碑档案”的混合结构，以 WI 记录有意义的变更，以 ADR 记录跨模块长期决策。`scripts/check-docs.mjs` 解析 Markdown 和 YAML，并纳入根 `pnpm check`。

## 验收标准

- 所有原 MVP 文档可以从 `v0.1-mvp/README.md` 访问。
- 文档内部链接、元数据、编号、目录索引和当前登记通过自动检查。
- 断链、重复编号、非法状态、缺失字段和未登记活动 WI 均有负向测试。
- lint、类型检查、全部测试和构建通过。

## 证据

- `pnpm check:docs`：通过。
- 文档校验器负向测试：5 个场景全部通过。
- `pnpm check`：通过；17 个测试文件、72 个测试，以及 lint、类型检查和构建全部通过。

## 交接说明

本工作项已完成，无残余实施任务。下一项候选是 `v0.2 自动截图`，但必须先由用户确认范围，再建立里程碑和新的活动 WI。
