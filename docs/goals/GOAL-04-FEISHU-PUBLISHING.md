# Goal 4：完成飞书发布闭环

> 对应技术方案：Publisher Interface、Feishu Adapter、飞书 Block 转换、图片上传、幂等更新和发布审计  
> 前置条件：[Goal 3：完成文档生成、截图与审核闭环](./GOAL-03-DOCUMENT-GENERATION.md) 已通过确认  
> 后续 Goal：[Goal 5：真实项目端到端验收](./GOAL-05-PILOT-VALIDATION.md)

## Goal

让一份已审核的 `DocumentationModel` 能够安全、可追踪、可重试地创建或更新到飞书测试知识空间，并保证重复发布不会产生重复目录或重复文档，未审核内容不能发布。

## 结果

- 固化小而稳定的 `Publisher` 接口及发布输入、输出和错误模型。
- 实现两个适配器：
  - `InMemoryPublisher`：用于契约测试；
  - `FeishuPublisher`：用于飞书测试知识空间。
- 使用飞书官方 Node SDK 封装以下能力：
  - 获取并刷新应用访问令牌；
  - 验证目标知识空间和父节点权限；
  - 创建或定位知识库目录节点；
  - 创建或定位对应飞书文档；
  - 将 `DocumentationModel` 直接转换为飞书 Block；
  - 上传截图并替换为飞书资源引用；
  - 分批写入或更新正文；
  - 处理限流、暂时性网络错误和可重试失败。
- 建立本地文档、文档修订、飞书节点和远端文档之间的持久化映射。
- 重复发布同一文档时更新既有远端文档，不创建重复内容。
- 发布操作记录目标、修订号、远端标识、开始/结束时间、结果和错误类别。
- 实现：

```bash
bizdoc publish feishu [--document <document-id>]
```

- 发布前展示目标知识空间、父目录、文档标题、修订号和图片数量。
- 明确区分配置错误、授权错误、内容转换错误、限流、网络错误和不可重试错误。
- 提供飞书测试知识空间的配置说明、权限清单和集成测试运行说明。

## 约束条件

- 只针对用户明确提供并授权的飞书测试知识空间进行开发和验证，不发布到生产知识空间。
- App ID、App Secret、访问令牌和其他凭证只从环境变量或安全存储读取，不写入仓库、配置文件、SQLite、日志或测试快照。
- 在缺少有效飞书凭证或知识空间授权时，不伪造集成测试成功；应完成本地适配器、契约测试并明确报告外部阻塞。
- 只有 `approved` 的明确文档修订允许发布；草稿、新修订和存在待审核项的内容必须返回 `REVIEW_REQUIRED`。
- 不直接把 Markdown 当作飞书正文上传；必须从 `DocumentationModel` 生成飞书 Block。
- 平台特有字段限制在 `publisher-feishu` 内，不得污染 `business-model` 或 `document-model`。
- 发布必须幂等，并以本地远端映射和稳定业务 ID 为依据，不能仅按标题模糊查找。
- 自动重试只适用于明确可重试的错误，使用有上限的指数退避并遵守飞书限流信息。
- 不无限重试授权错误、参数错误或内容不受支持错误。
- 远端部分写入失败时必须保留可诊断状态，不得把发布记录标记为成功。
- 不在本 Goal 实现 GitBook、独立 Help Center、批量全库发布或复杂审批流。
- 真实外部写入必须通过显式集成测试开关执行，默认测试不得修改飞书状态。

## 确认

- `InMemoryPublisher` 与 `FeishuPublisher` 通过同一套 Publisher 契约测试。
- 单元测试覆盖 DocumentationModel 到飞书 Block 的标题、段落、列表、表格、步骤和图片占位转换。
- 测试证明未审核文档、已被新修订取代但未重新审核的文档均无法发布。
- 测试证明同一已审核修订连续发布两次只对应一个远端目录节点和一份远端文档。
- 测试证明更新后的已审核修订会更新既有远端文档，并保存新的发布记录。
- 模拟 429 和暂时性 5xx 时执行有上限重试；模拟 401/403 和无效 Block 时不做无意义重试。
- 模拟图片上传或正文写入中途失败时，发布记录为失败或部分失败，并能够再次安全执行。
- 日志和数据库检查确认不存在 App Secret、访问令牌或 Authorization Header 明文。
- 在获得测试凭证后，真实集成测试完成：创建目录、创建文档、写入标题/段落/列表/表格、上传图片和更新已有文档。
- 人工在飞书测试知识空间审查排版、图片位置、目录层级和重复发布结果。
- 根目录 `build`、`lint`、`typecheck`、`test` 全部通过；外部集成测试结果单独报告。
- Goal 结束时列出远端测试对象、幂等验证结果、限流策略、权限要求、未覆盖的飞书 Block 和进入 Goal 5 的前置条件。

## 完成边界

本 Goal 在“已审核文档可幂等发布到飞书测试知识空间”后结束。没有有效凭证时不得声称完整飞书闭环已经完成。
