# 开发流程

## 开始工作

1. 按 [开发文档中心](../README.md) 的顺序读取当前状态和交接。
2. 检查 Git 工作树，保留不属于当前任务的已有改动。
3. 确认活动 WI 的结果、范围、约束和验收标准。
4. 若没有活动 WI，先创建并登记工作项；候选路线图不能直接作为开发授权。

## 实施过程

- 工作项进入开发时设为 `in_progress`，并列入 `current/STATUS.md` 与 `current/HANDOFF.md`。
- 范围或公共契约变化时先更新 WI；跨模块长期决策使用 ADR。
- 代码、测试和当前文档在同一工作项中同步更新。
- 凭证、企业路径和外部系统临时状态不得写入仓库。

## 完成工作

1. 运行 WI 约定的定向测试和完整 `pnpm check`。
2. 在 WI 的“证据”中记录实际命令、结果和仍存在的风险。
3. 将 WI 设为 `done` 并移至 `work-items/completed/`。
4. 更新当前需求、架构、ADR 和使用说明中受影响的内容。
5. 更新 `STATUS`、`HANDOFF`、`CHANGELOG` 和里程碑索引。
6. 只有在用户明确要求时才提交或推送 Git 变更。
