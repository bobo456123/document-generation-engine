# 当前路线图

以下内容迁移自 MVP PRD 的后续版本设想，当前全部为 `proposed`。版本号、顺序和范围都可以在建立正式里程碑前调整。

| 候选版本 | 状态 | 目标能力 | 建立里程碑前需要确认 |
|---|---|---|---|
| v0.2 | `proposed` | 基于 Playwright 的登录、页面定位、自动截图、压缩和功能关联 | 登录方式、支持站点范围、脱敏责任、失败回退 |
| v0.3 | `proposed` | 从 Git Diff 推导业务模型变化、影响功能和待更新文档 | 基线选择、增量准确率、人工确认门禁 |
| v0.4 | `proposed` | 根据业务变化生成 Change Log、影响角色和业务影响 | 输出格式、发布位置、与文档修订关系 |
| v0.5 | `proposed` | 接入 PRD、Wiki、数据库、API、制度和产品资料，形成统一上下文 | 数据权限、来源优先级、更新策略、是否引入 RAG |
| v1.0 | `proposed` | 独立 Help Center，包括搜索、分类、权限、版本、审核、评论、问答和分析 | 产品价值验证、部署形态、身份与权限模型 |

## 推进规则

候选方向只有在用户确认结果、边界和验收标准后，才能：

1. 使用[里程碑模板](../templates/MILESTONE.md)创建对应版本目录。
2. 将里程碑状态从 `proposed` 调整为 `active`。
3. 使用[工作项模板](../templates/WORK-ITEM.md)创建可执行的活动工作项。
4. 在[当前状态](./STATUS.md)和[当前交接](./HANDOFF.md)登记活动编号。
