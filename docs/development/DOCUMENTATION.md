# 文档治理规范

## 命名与语言

- 路径和文件名使用英文，正文使用中文。
- 工作项编号为 `WI-0001`，ADR 编号为 `ADR-0001`，编号全局唯一且不复用。
- 日期使用 `YYYY-MM-DD`，版本使用 `v0.2` 或发布版本 `v0.2.0`。

## 工作项规则

- 一个有意义的功能、修复或技术改进对应一个 WI，不记录每日聊天流水。
- 活动文件位于 `work-items/active/`，完成或取消后移入 `work-items/completed/`。
- 状态只能是 `proposed`、`ready`、`in_progress`、`blocked`、`done`、`cancelled`。
- WI 必须包含结果、背景、范围、约束、实施方案、验收标准、证据和交接说明。

## 里程碑规则

- 路线图中的 `proposed` 方向只有经用户确认范围后才能建立里程碑。
- 活动里程碑的 README 索引所属 WI、ADR、验收标准和风险。
- 关闭里程碑时写入完成日期、结论和验证证据，并在 CHANGELOG 中追加版本摘要。
- 已关闭里程碑视为历史事实，不再随当前实现改写；勘误必须注明日期和原因。

## 当前文档与交接

- `current/HANDOFF.md` 是唯一当前交接文件，模板和历史资料不能冒充当前状态。
- 开始任务时登记活动 WI；结束任务时记录最后验证提交或工作树状态、实际测试结果、下一项行动和阻塞。
- 当前需求和架构随已交付行为更新，不能把未来设想写成已经支持的能力。

## 自动检查

`pnpm check:docs` 验证内部链接、元数据、编号、状态、目录索引和活动工作项登记。检查通过只证明文档结构一致，内容正确性仍由工作项和里程碑验收负责。
